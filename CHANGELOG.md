# VaultPass Desktop - Changelog

## [Unreleased]
LAN sync with VaultPass for Android, rebuilt for security and reliability. Update both apps together: this version can't sync with older versions, and every phone must be paired again once.

### Added
- **Reviewed sync that ends identical on both devices:** The device that starts a sync reviews every difference and chooses what happens to each entry; conflicts must be answered. The other device sees a summary and applies or declines it. Both apply the same changes and compare a fingerprint of their vaults, so a sync only reports success when the two vaults match.
- **Deletions sync:** Entries deleted on one device, including ones purged from the Recycle Bin, are deleted on the other device too.
- **Custom fields:** Entries can hold custom fields, edited in the entry dialog, and they sync with the phone.
- **Sync errors you can read:** Every failed sync opens the error dialog with its reason, and the other device is told why the sync stopped.
- **Waiting and approval dialogs:** While the phone reviews a sync, this PC shows a waiting dialog with Cancel. When the phone sends its changes, this PC shows what will change before applying it.
- **Update banner and dialog:** When the update check finds a newer version, a banner after unlock offers Update and Not now. The download shows its progress and can be cancelled. When the update is ready, Restart now closes VaultPass after a 2-second countdown, installs the update and opens VaultPass again. Later installs it when you close VaultPass, but never while Windows is shutting down or signing out; if Windows shuts down or signs out instead, the next start says the update wasn't installed. Restart now waits while a sync, backup, import or export is running or an entry is open.
- **Update that didn't install:** If VaultPass is still on the old version after an update was started, it shows "The update to X.Y.Z didn't install." with Show details (Setup's log) and Try again.
- **Database backup before an upgrade:** Before VaultPass upgrades the vault database to a new schema, it saves a copy as `vaultpass.db.before-schema-vN.bak` next to it and checks that the copy is intact and has the same number of entries. Only the newest of these backups is kept. If the backup fails, the database is not upgraded.
- **Vault found in another folder:** If the data folder has no vault but another known folder has one (the folder VaultPass used last, `C:\VaultPass\data`, or a folder older versions switched to on their own), VaultPass offers Copy it here, Start a new vault (asks for a second click) and Close. When more than one folder has a vault, it offers the most recently changed one and lists the others. Copy it here copies the database with SQLite rather than as a plain file. A database already in the data folder is renamed aside first, together with its `-wal` and `-shm` files under matching names. The original stays where it was.

### Changed
- **Networking only while syncing:** Discovery and the sync listener run only while Settings > Sync is open or a pairing QR code is shown, and stop when the vault locks.
- **Firewall rules:** The rules for TCP 53853 and UDP 53852 now apply to Private networks only. Older rules that covered every network profile are removed.
- **Database:** Schema changes are tracked with SQLite `user_version` migrations. The `sync_tombstone` table records deleted entries for sync. Entries that can't be decrypted are marked and left out of sync.
- **Larger vaults:** Entries are sent in parts of about 1 MB.
- **Editor limits shared with the phone:** Title 200 characters, username 300, password 1,000, website 500, notes 20,000, custom field name 100 and value 2,000, up to 50 custom fields and 25 tags. Save is blocked with a message while a field is over its limit.
- **Settings and the Privacy Policy** now name the key derivation the vault really uses: PBKDF2-HMAC-SHA256. They previously said Argon2id.
- **Update check off by default for new installs:** The setting is now called "Check for updates when VaultPass opens" and is off for new installs. Existing installs keep their setting. All settings are now written to `settings.json`, so a later change of a default can't change them.
- **VaultPass reopens after an update:** An update started with Restart now opens VaultPass again when Setup finishes. If the update fails before Setup has copied its files, the old version starts and shows that the update didn't install. If it fails after the old files were removed, Setup opens again so you can finish the installation. The update from 1.1.0 is still run by 1.1.0's own updater, so VaultPass doesn't reopen after that one; open it from the Start menu.
- **Update downloads in the data folder:** Installers download into the `updates` folder inside the data folder instead of `%TEMP%`. The file is saved as `.part` and gets its real name only after its signature verifies. Old installers, partial downloads and Setup logs older than 30 days are deleted.
- **Install folder:** New installs go to `%LOCALAPPDATA%\Programs\VaultPass` by default. Updates stay in the folder already in use. A new install offers the folder of the vault VaultPass used last, or `C:\VaultPass` when a vault is still there. The installer refuses the root of a drive. It accepts a folder that isn't empty only when it holds `VaultPass.exe`, is the folder of the registered VaultPass install, or holds only the `data` folder an uninstall left behind. Setup writes a log.
- **Data folder:** VaultPass no longer switches to another folder when it can't write to its data folder. It shows the folder and the reason, with Retry and Close. VaultPass remembers its data folder in `HKCU\Software\VaultPass\DataDir`, and the installer uses it to offer the same folder after a reinstall.
- **Clearer errors:** A vault database that can't be opened is no longer reported as corruption; the message gives the real reason. A vault saved by a newer version of VaultPass shows a message with Check for updates and is left unchanged. The error screen has a Close button.
- **Release script:** `build-installer.ps1` stops before building when `version.txt` isn't a version like 1.2.3 (exit code 4), or when it isn't higher than every release on GitHub or every signed installer already in `dist\` or `launch\` (exit code 3).

### Security
- **Signed updates:** The updater installs a release only if its `.sig` file verifies with the VaultPass release key built into the app; the signature covers the installer's version, so an older installer can't be passed off as a newer one, and checks GitHub's SHA-256 digest when one is published. Only `major.minor.patch` release tags count as updates, and only the asset named exactly `VaultPass-Setup-v<version>.exe` is downloaded. Unsigned, altered or unexpectedly changed installers are deleted and not run. Before launch the installer is re-checked while VaultPass holds it locked against changes and deletion until Windows has started it; this narrows, but does not remove, the time in which another program could swap the downloaded file. Downloads are https only and capped at 500 MB. A build without the release key reports "Updates are disabled". Release steps are in RELEASING.md.
- **Release signing:** Installers are signed by `tools/SignInstaller.java`, run by `build-installer.ps1`, which reads the key password at a hidden prompt (never from an environment variable), refuses pre-release versions and installers whose app has no embedded key, and checks every new signature with the app's own verifier. The bundled Java runtime explicitly includes `jdk.crypto.ec`, which the signature check needs.
- **Sync protocol v2:** Each connection starts with a P-256 key exchange authenticated by the pairing key, and every message is encrypted with AES-256-GCM using a key and a counter per direction. A replayed, reordered or altered message ends the connection.
- **The QR code holds a one-time secret** that never goes over the network, and a new phone must be approved on this PC. Pairing keys are stored encrypted with the vault key. Pairings from the old protocol, whose keys were sent and stored in plain text, are deleted.
- **Discovery beacons carry no device name or ID**, and a recorded beacon can't redirect a device to another address.
- **Random device ID:** This PC's sync identity is a random ID stored in the `sync-device-id` file in its data folder.
- **One sync connection at a time:** Other devices are turned away while a sync is in progress.
- **Install folder limited to your account:** On every install and update, the installer limits the install folder and everything inside it, including the vault in its `data` folder, to your Windows account, SYSTEM and Administrators, and makes your account the owner of every item in it. Links inside the folder are changed themselves but never followed, so nothing outside the folder is changed. Other Windows accounts on the same PC can no longer open this install or its vault. Where that can't be done (for example on a FAT32 or exFAT drive), the installer says so and VaultPass shows a warning with the reason after unlock until a reinstall succeeds.
- **Planted program files removed:** Before copying its files into a folder that already holds VaultPass, the installer removes the `.dll`, `.manifest`, `.cfg` and `.local` files directly in the install folder, every `.exe` there except `VaultPass.exe` and the uninstaller, and `.local` folders, and it replaces the `app` and `runtime` folders. Other files directly in the install folder, such as the uninstaller's log `unins000.dat`, and the files inside `data` are not removed; the permission lock-down above covers them.
- **In-app updates only for an installed copy:** VaultPass updates itself only when it runs from the folder its Setup program registered. Any other copy says "This copy of VaultPass wasn't installed by its Setup program, so it can't update itself. Download the installer from GitHub instead."
- **Before an update starts:** VaultPass stops sync, clears a password it copied to the clipboard, locks the vault and closes the database.

### Fixed
- Finish in the sync review no longer races its own cancel, so the phone is always told the sync finished.
- The phone finishing its sync no longer closes a review that is still open on this PC.
- The sync time limit now restarts with each part received, so large vaults no longer time out mid-transfer.
- A `metadata.json` that can't be read no longer opens the Setup screen, where creating a vault would have replaced it. VaultPass shows the file and the reason and changes nothing. Setup never creates a vault over an existing `metadata.json` or a database that holds entries.
- When `vaultpass.db` or `metadata.json` is missing while the other is there, VaultPass says which file is missing instead of creating an empty vault.
- A failed database open no longer leaves a half-opened connection behind; the next attempt runs every check again.
- A rollback journal left next to the vault database by an interrupted write (a hot journal) no longer stops VaultPass from opening the vault.
- A failure while VaultPass starts now shows an error with the reason instead of a spinner that never ends.
